# Inference and Matching — Assumptions and Limitations

> **TL;DR** — `/document/infer` is fully synchronous: embedding + Milvus search + sequential LLM calls all happen in a single HTTP request, so large result sets can time out. Compatibility score is mean cosine distance (all chunks weighted equally). Session IDs have no auth. The `hybrid` knowledge-feed mode currently behaves identically to `text` — image multimodal is not wired through.

## Assumptions

| #   | Assumption                                                                                                                                                                                                                                                                                                 | Limitation it introduces                                                                                                                                                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **`/document/infer` runs synchronously.** The entire inference pipeline — query embedding, Milvus search, document scoring, per-chunk LLM question generation, and report upload — executes within a single HTTP request.                                                                                  | For large result sets (high `limit` × `group_size` × `questions_per_top_chunks`), the request can time out or block the server thread for minutes. Unlike ingestion, there is no background task option for inference.                                                   |
| 2   | **Compatibility score is the arithmetic mean of chunk cosine distances.** `generate_doc_match_report` computes `np.mean(scores)` across all chunk hits for a document as its document-level compatibility score (`scoring.py:46`).                                                                         | Mean averaging treats all chunks equally regardless of their ranking or spread. A document with one very relevant chunk and many irrelevant ones will score the same as a document with uniformly moderate relevance. No weighting, decay, or max-pooling is applied.    |
| 3   | **Topic filter is an exact string match.** Milvus search is filtered via `expr=f'topic == "{topic.value}"'`.                                                                                                                                                                                               | All ingested documents must be stored under a matching topic value at ingest time. Cross-topic search or partial matching is not supported. A document ingested under a mismatched topic will never appear in search results.                                            |
| 4   | **System prompt is injected as a `role="user"` message.** In `_build_chat_messages`, the `CHATBOT_SYSTEM_PROMPT` is prepended as a `ChatMessage(role="user", ...)` rather than `role="system"` (`matcher_router.py:171`).                                                                                  | Models that distinguish system vs. user roles (e.g., OpenAI GPT, Gemini) may not honour the grounding instructions with the same weight as a proper system message. The chatbot may be more prone to ignoring the "answer only from context" constraint.                 |
| 5   | **Chat history is capped at the last 5 turns.** `redis_client.get_recent_messages(session_id, 5)` is hardcoded in `chat_with_llm` (`matcher_router.py:208`).                                                                                                                                               | Earlier conversation context is silently dropped. For long diagnostic sessions, the LLM loses awareness of prior exchanges. The cap is not configurable via API or environment variable.                                                                                 |
| 6   | **`_search_corpus` uses hardcoded `limit=5, group_size=2`.** The helper used by the `/document/chat` endpoint fixes retrieval parameters regardless of query complexity (`matcher_router.py:103-109`).                                                                                                     | The chat endpoint cannot be tuned for broader or narrower retrieval at runtime. A query needing deeper coverage is always limited to 5 documents × 2 chunks each, independent of corpus size.                                                                            |
| 7   | **LLM output is expected to be strict valid JSON.** All four prompt templates (`SUBJECTIVE`, `MCQ`, `MATCH_MAKING`, `ONE_WORD`) instruct the LLM to return only a JSON object with no wrapping text or markdown fences.                                                                                    | If the LLM returns malformed JSON, extra commentary, or markdown code fences, parsing will fail or the raw string will be stored under `llm_resp.raw` with no structured questions. There is no retry, repair, or fallback logic for malformed LLM responses.            |
| 8   | **`hybrid` knowledge feed mode does not actually pass images to the LLM.** In `rag_pipeline.py:231-233`, both `image` and `hybrid` modes send the same text-only `messages` list to `llm_client.chat()`. The image URL is appended to the prompt string but is not passed as a multimodal message payload. | The `hybrid` mode behaves identically to `text` mode at the LLM call level. The image URL appears in the prompt text but the LLM receives no actual image data unless the model interprets the URL string. True multimodal grounding is not implemented.                 |
| 9   | **Presigned URLs expire in 1 hour.** Document URLs and PDF page image URLs in both `/document/infer` responses and chat sources use `expires_seconds=3600` (`scoring.py:43`, `matcher_router.py:134`, `matcher_router.py:142`).                                                                            | Any presigned URL stored in a client, report, or Redis history becomes invalid after 1 hour. Saved reports or cached API responses will contain dead links.                                                                                                              |
| 10  | **Session IDs have no authentication or ownership.** Any caller who knows a `session_id` UUID can read or clear that session's history. Session IDs are auto-generated UUIDs but are transmitted in plain query parameters.                                                                                | There is no token, signature, or user binding on sessions. In a multi-user deployment, session IDs can be guessed or intercepted. `DELETE /mavenir-rag/document/session` allows anyone to destroy any session without authorisation.                                           |
| 11  | **Report file name is always `sample_report.md`.** `generate_markdown_report` is called with a hardcoded `output_md_file_path="sample_report.md"` in `rag_pipeline.py:143`.                                                                                                                                | Every inference call writes to and reads from the same local filename. Under concurrent inference requests, two reports can overwrite each other on disk before the upload to MinIO completes, corrupting one report. The local file is also never deleted after upload. |

## Limitations

| #   | Limitation                                                                                                                                                                                                                                                  | Impact                                                                                                                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **MinIO is queried twice per matched document in scoring.** `generate_doc_match_report` calls `minio_client.list_objects()` at line 38 to get the doc URL, then calls it again at lines 62–65 to get the filename (`scoring.py`).                           | For a result set with `limit=10` documents, this is 20 MinIO `list_objects` calls per input query, all within a single synchronous HTTP request. Latency grows linearly with the number of matched documents.                                           |
| 2   | **No relevance threshold on search results.** Milvus returns the top-`limit` documents regardless of how low their similarity scores are.                                                                                                                   | Completely unrelated documents are included in the response if the corpus has fewer high-quality matches than `limit`. There is no minimum score cutoff to filter out low-confidence matches.                                                           |
| 3   | **Question generation is fully sequential.** `generate_questions_from_chunks` iterates over every matched chunk for every input query and calls `llm_client.chat()` one at a time (`rag_pipeline.py:183-245`).                                              | With `limit=5`, `group_size=2`, and `questions_per_top_chunks=2` across 3 input queries, that is up to 30 sequential LLM calls in a single request. Total latency equals the sum of all LLM round-trips with no parallelism.                            |
| 4   | **`generate_doc_match_report` silently returns `None` on missing objects.** If `minio_client.list_objects()` returns empty for any matched doc at line 39–40, the function returns `None` rather than continuing to the next document (`scoring.py:39-40`). | A single missing or deleted MinIO object for any matched document aborts the entire scoring loop. The caller receives `None` instead of a partial result, causing the inference pipeline to fail for all queries even if only one document is affected. |
| 5   | **Chat context is capped at 10,000 characters.** A debug `print` in `chat_with_llm` slices context to `[:10000]` (`matcher_router.py:205`), and the full context string passed to the LLM is bounded by token limits of the underlying model.               | For dense corpus chunks, relevant information may be truncated before reaching the LLM. There is no chunking or summarisation of context before injection.                                                                                              |
| 6   | **No deduplication of chunk sources.** If the same corpus chunk matches multiple input queries, it is independently processed and billed to the LLM for each query.                                                                                         | Redundant LLM calls occur for shared high-ranking chunks. Reports contain repeated question sets for the same content.                                                                                                                                  |
| 7   | **`print` statements remain in production inference code.** `rag_pipeline.py:234-235` prints the full prompt and LLM response to stdout on every question generation call.                                                                                  | In production, this leaks potentially sensitive document content to server logs and slows down high-throughput inference due to synchronous stdout flushing.                                                                                            |
